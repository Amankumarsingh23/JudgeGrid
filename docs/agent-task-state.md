# Task state and recovery

Migration 0021 records immutable source scope, provider, policy, user goal and target. Exact archived child IDs are attached once. CREATED reserves one research child. RESEARCHING reconciles its verified completed output. PLANNING goes to PREPARING_WORKSPACE, COMPLETED_RESEARCH or STOPPED_UNRESOLVED. Workspace prep enters VALIDATING_BASELINE. An actionable unpassed baseline advances to REPAIRING. The existing child repair controls WAITING_APPROVAL, applying and validating; a first failed fix can return to REPAIRING for a second proposal. Terminal states separate pass, unresolved, denied, infrastructure and cancellation.

The task uses a DB-clock claim with monotonic generation. The same task UUID identifies the research child. Workspace prep is idempotent by research run. Validation uses its exact selected-version identity, and repair uses its scoped current-version/baseline identity. The parent reuses committed child receipts after interruption. Child mutations follow a fixed lock order from task to repair to workspace or validation. The parent lock covers bounded dispatch and publication operations, not a running sandbox. Expired generations cannot authorize new child work or publish a task report. Recovering authoritative state does not imply each physical operation ran once.

The parent reserves at most 12 research dispatches, three logical validations including baseline and two approved repair iterations. Existing child limits cap individual physical attempts. It allows five planner calls, 8192 input tokens, 4096 output tokens, 64 KiB of admitted context, 32 claims, one active lifecycle with a 30-minute overall deadline and a 12-minute active-claim allowance. Per-owner admission limits two live tasks and six in one hour. Child retries do not replenish these limits. Active time is charged on release or takeover up to the lease endpoint. The approval wait is visible separately between WAITING_APPROVAL and the exact grant event. Aggregate wall time includes any unclaimed wait.

Cancellation revokes the parent claim before invoking child cleanup. Attached selected workspace versions and child reports remain immutable. A previous committed edit is not rolled back. The controller seals successful, denied, infra-blocked and unresolved reports after verifying child evidence. Explicit cancellation and lease/budget exhaustion can leave only the durable status and child history if no final evidence can be sealed.
