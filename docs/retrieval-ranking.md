# Retrieval ranking contract

Each exact retained analysis chunk is a candidate document, including PARSED, PARTIAL and UNSUPPORTED eligible text. EXCLUDED source entries never had analysis chunks and cannot enter retrieval. Exact duplicate `(analysis file ID,start,end)` ranges collapse deterministically to the lowest chunk ID; exclusions and reasons are in the retrieval manifest. Source/analysis data is never rewritten.

Four independent token fields are qualified symbol (weight **4**), exact identifier-shaped source words (**2**), path (**1.5**) and source body (**1**). The full body includes existing comments/docstrings within the bounded chunk. Tokenization preserves case-sensitive `=identifier`, lowercased whole words, snake components, camel/Pascal boundaries and acronym boundaries (`HTTPServer` -> `http`, `server`). Paths split at separators/dots; nonletter/digit/underscore text is a boundary. Unicode letters/digits are retained, tokens above 256 bytes are omitted, and neither stemming nor stop-word removal is used. Tokens represent lexical words, not compiler-proven identifier bindings. Query terms are unique within each field; repeat query words do not inflate the score. Exact whole tokens are matched; substring/SQL wildcard search is not used.

For each field, BM25 uses k1=**1.2**, b=**0.75**, full deduplicated corpus document count N, per-field df, token frequency, field length and mean field length. It sums `weight * log(1+(N-df+.5)/(df+.5)) * tf*(k1+1)/(tf+k1*(1-b+b*length/avgLength))`. Empty fields contribute zero. Corpus statistics remain those of the exact immutable index even when a query applies a filter; no other owner's statistics participate. Field/channel weights and bounded k1/b are explicit policy settings, not experimentally optimized defaults.

Parent/nested chunks can still share text. Their overlap affects the explicitly defined corpus statistics; counts are not unique-source-byte coverage. Final ranking suppresses a same-file candidate if its intersection with a previously selected result is at least 80% of the shorter range. It keeps the original indexed evidence and raw channel ranks. This is conservative display diversity, not source deletion or context assembly. Bounded candidate depths can therefore produce fewer diverse results than topK.

Exact dense ranking uses pgvector cosine distance over the same authorized READY index. Lower distance is better; similarity is `1-distance`, not a calibrated relevance probability. HNSW is opt-in with its own graph per index. SQL owner/index/snapshot/analysis predicates and allowed chunk IDs are applied in the authoritative query. The graph can still underfill under selective filters. If it returns fewer than the bounded intended depth or a filter selects less than one quarter of the corpus, search runs exact fallback. The default remains exact, suitable for this small corpus. ANN recall must be measured against this baseline; full candidate count alone is not a recall guarantee.

Hybrid unions lexical and dense candidates by immutable chunk ID, then scores `wLex/(60+lexRank) + wDense/(60+denseRank)` for present channels, with one-based ranks and default weights 1/1. Missing channels contribute zero. Raw BM25 and cosine scores are never added. Stable ties use ascending chunk ID. TopK is 1..50, per-channel depth is topK..200; each database similarity statement has a five-second timeout and overall search has a 15-second bound including verified source reads. Request mode/filter/depth are explicit inputs. There is no extra exact-name/path boost beyond versioned BM25 fields, and no boosted policy has been promoted without a comparative evaluation.

Returned candidates include original analysis chunk/symbol/file/range/hash, source parse state, lexical and dense ranks/scores and fusion score. Search verifies each returned span again through the owner-scoped analysis reader. PARTIAL/UNSUPPORTED statuses remain visible, and syntax graph candidates are never treated as semantic truth. Source text is evidence, never executable instructions.

Primary reference: [pgvector exact/approximate search and filtering](https://github.com/pgvector/pgvector/tree/v0.8.2).
