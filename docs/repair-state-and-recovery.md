# Repair state and recovery

Migration 0020 stores the exact workspace and research ancestry, baseline request and report digest, pinned profile, image, planner and target. It tracks the current selected version, child validation, monotonic budgets, physical claim generations, immutable event rows and completed iteration receipts. The terminal inspection identifies the source commit and snapshot and fingerprints the scoped history using canonical timestamps. The child validation reader verifies the stored report and log digests independently.

BASELINE_VERIFIED permits diagnosis. A bounded proposal advances DIAGNOSING to WAITING_APPROVAL. An exact grant allows APPLYING and then VALIDATING. Actionable failure can enter ITERATION_FAILED. A successful required test run enters COMPLETED_VALIDATED. Insufficient evidence, denied or expired approval, policy mismatch, infrastructure and exhausted budgets have separate outcomes. CANCELLED invalidates the parent claim and attempts to revoke its unpublished approval or reconcile its recorded child validation. A previously committed workspace version is never rolled back by cancellation.

A repair consumes one baseline plus at most two new logical validations. It reserves each proposal attempt before asking the proposer or processing a manual submission. It allows four proposal attempts, 40 claim generations, 32 KiB total inspected patch bytes and a 25-minute deadline. Each worker claim lasts at most five minutes by database time. A proposer gets three seconds. The underlying application and sandbox keep their existing limits. An unchanged patch, repeated postimage or return to a previous failing source hash is denied.

A parent lease revalidates ownership and generation while Session 18 claims or publishes a patch and while Session 19 creates, starts or publishes validation work. Child transactions continue to enforce their own authority. A suspended process can leave unselected staged objects or an incomplete child attempt. A replacement uses the exact immutable patch and validation receipts. An orphaned pending child request after a parent transaction interruption cannot dispatch under the stale parent. Validation on an unchanged request remains idempotent.

Repair inspection exposes ordered events, including request, grant, apply and child-validation timestamps. Proposal duration includes diagnosis and preflight. Validation duration, resource observations and digests come from the child report. Targeted fault tests simulate a lost controller after patch publication and after validation completion. The replacement cannot manufacture a final result if either child lacks its authoritative receipt.
