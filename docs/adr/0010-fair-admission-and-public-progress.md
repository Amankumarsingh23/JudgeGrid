# ADR 0010: shared fair admission, local sessions and durable progress

Status: accepted, Session 10.

PostgreSQL already owns submissions, logical rejudge jobs, attempts and fenced result writes. Redis delivery order cannot provide fair execution across independent controllers, and an in-memory rate limiter cannot enforce shared API limits. A global sequence alone cannot safely represent transaction commit order for reconnecting clients.

We add an explicitly enabled scheduler policy and at most 128 enrolled principals. Under a short transaction advisory lock, admission selects the least recently admitted eligible principal, then its oldest pending logical scope by `(created_at, scope UUID)`. Valid active work is skipped within a bounded 17-row head search because there can be at most 16 active leases globally. Selection examines at most 128 principals. Expired/retry attempts retain their original queue position but must obtain a new fair turn. Published outbox intent remains mandatory. The same permit and capacity guards apply to initial work and rejudges, before the existing ownership transaction grants a generation. No execution occurs under the scheduler lock.

Redis is a durable notification transport. Fair agents validate and acknowledge notifications; bounded database polling selects executable work even after notifications disappear. A failed publication cannot become eligible, duplicate notifications cannot mint extra attempts, and scanner recovery cannot bypass admission. Races on a stale candidate defer until the next bounded poll instead of requeueing it. Standalone local execution has no capacity bypass. CLI agents require explicit fair mode and a scope covering all enrolled principals; scope changes require restarting controllers. Legacy non-fair behavior remains available only with scheduler policy disabled.

With capacity becoming available, an eligible continuously backlogged principal receives a turn after at most the other eligible enrolled principals have been admitted once. Per-principal limits must be below a multi-slot global limit; single-slot operation allows a limit of one. Guarantees concern *valid database execution leases*, not equal completion times or physical orphan containers. A crashed container can exist until the established authority-based reconciler removes it. The head must have published intent and be due; retry backoff can deliberately block later work from the same principal. Fairness assumes the enrolled set is bounded, agents cover it, leases/heartbeats and the database operate, and turns continue becoming available. Disabled historical principals do not silently join the fair pool.

Creation and rejudge insertion share a per-principal pending budget, including active logical jobs until terminal state. HTTP submission requests spend a database token before decoding or replay resolution; invalid/replayed requests cannot undo consumption. A row lock, database time and independent commit enforce refill across API instances. Login has separate shared global and account buckets. Existing outbox-backlog admission remains. Request rate/pending/SSE capacity errors return 429 with Retry-After; deferred scheduler admission/infrastructure/backlog return 503. Replayed POSTs create no new pending work but still spend rate tokens.

The browser is an explicit trusted development mode. An offline operator provisions users; PBKDF2-HMAC-SHA256 uses a random salt and 210,000 iterations. Random opaque sessions are stored only as SHA-256 token hashes, expire after 30 minutes and revoke through the database. HttpOnly, SameSite=Strict cookies are Secure under HTTPS; HTTP is allowed only for an exact loopback development origin. Origin/Host checks and a separate session CSRF token protect mutations. Browser JavaScript receives no privileged development key. Forged identity headers are ignored. Every private read, history, pagination predicate and SSE subscription uses the authenticated owner. Cursors include owner binding but are not cryptographically signed: authorization still comes from SQL owner predicates. Foreign/missing resources receive the same 404 before cursor parsing. Production defaults remain unauthenticated/closed.

Public events have an allowlisted type, JSON keys, bounded payload and immutable `(submission_id, seq)` identity. Updating a per-submission counter holds that row lock until transaction commit: B cannot allocate a later sequence and commit ahead of A. Rollback also rolls back allocation. Business-state triggers append in their own transaction. Actual Docker StartedAt observation appends fenced compiling/running events; cache restores are preparing, never fabricated compiler progress. Failure reasons are reduced to safe fixed codes. Progress-observation failures fail closed through infrastructure handling.

SSE fits a server-to-browser status stream; polling remains the bounded internal wake-up mechanism, and WebSocket's bidirectional protocol is unnecessary here. A repeatable-read snapshot captures public state and its journal boundary together. Reconnect replays committed events after a submission-scoped Last-Event-ID through that boundary, then emits the snapshot and polls after it. Mutations during snapshot/subscription setup therefore remain readable. Pages are at most 32, lag/replay at most 256; excessive/missing history produces an authoritative reset. Future cursors fail with 409. Per-connection memory is bounded; five-second write deadlines and lag resets terminate slow consumers. Shared 30-second connection leases renew every ten seconds; crash capacity expires. Heartbeat comments, explicit flush, cache/proxy headers, two-minute stream rotation and cancellation bound transport lifetime. Session authorization is rechecked every poll; database failure ends a stream for safe reconnect.

No event retention pruning is implemented. The per-stream window is not a database retention policy. Expired login-session/bucket housekeeping, query optimization at larger scale, production identity/TLS, stronger production deployment and Session 11 telemetry remain follow-up work. Existing Docker/shared-kernel, physical-orphan, aggregate volume-quota, archived MinIO and privileged-operator risks remain.

Primary references: [WHATWG event streams](https://html.spec.whatwg.org/multipage/server-sent-events.html), [Go HTTP ResponseController](https://pkg.go.dev/net/http#ResponseController), [PBKDF2 implementation](https://pkg.go.dev/golang.org/x/crypto/pbkdf2). Runtime decisions and measured limits are verified by this repository's integration tests.
