# ADR 0011: optional bounded telemetry, independent of execution authority

Status: accepted for Session 11, following `b5dc002`.

Use OpenTelemetry Go API/SDK and OTLP/HTTP exporter **1.46.0**, with **client_golang 1.23.2** for a single direct Prometheus exposition path. Prometheus **3.15.1** stores metrics; Tempo **3.1.1** receives and stores OTLP traces; Grafana **13.3.0** provisions both data sources and four dashboards. Versions are explicit in go.mod/go.sum and the optional Compose overlay. The selected releases/configuration were checked against upstream sources and actual local startup, not assumed from an example for a different Tempo release.

A Collector is unnecessary for this bounded single-host deployment: applications export OTLP directly to Tempo's explicitly enabled HTTP receiver. Prometheus has explicit scrape targets for the API, relay and two native agents. Neither Grafana nor a Collector is mistaken for trace storage. The observability profile is opt-in, loopback-published, resource-limited and independent of the ordinary application's startup/dependencies. Grafana's anonymous account is a local Viewer only. Production defaults start no exporter or metrics listener. No Docker authority, source, hidden tests or object-store secrets enter these services.

Every process owns one private registry/provider. Bounded operation/outcome/language categories control metric cardinality. HTTP routes are categories, never raw URLs. Traces contain phase, language, outcome and standard HTTP/resource fields, with at most 16 attributes, four causal links and no arbitrary span events or raw exception recording. Operation logs include trace/span IDs at selected lifecycle boundaries; metric labels never include either ID. Debug-level poll/heartbeat logs avoid an INFO log per scheduler poll. Telemetry contains no principal, source hash, object key, source/test content, cookie or CSRF token.

Public HTTP trace headers are deliberately ignored. Migration 0013 captures the locally generated producer context in the existing outbox transaction and protects it against mutation. Original payload types 2/3 remain valid; wire schemas 4/5 add one validated traceparent field to initial/rejudge notifications. Old schemas remain supported. Invalid trace metadata loses correlation rather than granting authority or changing work. Relay physical attempts and message processing use new roots with causal links. Execution reads the authoritative producer context from PostgreSQL, including recovery after Redis retention. Multiple physical attempts link to one logical producer; trace context never substitutes for owner/run/generation checks.

Export uses a nonblocking 128-span channel, at most 16 spans per batch, a 250 ms timer and a 500 ms network deadline, with exporter retries disabled. Full queues increment a drop counter; export errors count lost exported spans. Shutdown has a bounded drain and cancellation budget. No export happens synchronously in a transaction, heartbeat or sandbox deadline. A missing receiver or occupied metrics port does not prevent work. Invalid explicit telemetry configuration is rejected rather than silently exposing a listener. Tests cover absent/stopped receivers, bounded capacity, shutdown, malformed context, cardinality and failure isolation.

The API alone polls cluster database gauges every five seconds, under a one-second statement context and bounded inventories. Prometheus scrapes only cached state and local counters/histograms. Each outbox status and other inventory is capped at 10001 rows; truncation and last-success time are exposed. Counters describe observed committed outcomes, not a new durable billing ledger. SDK metrics can reset or be lost across restarts; PostgreSQL remains authoritative. Long-running SSE HTTP durations, overlapping phase intervals and timestamp-derived estimates are explicitly distinguished.

No new judging capability, production authentication, automatic retention of application data, repository ingestion or Session 12 RAG work is introduced. Tempo's development trace storage is ephemeral; exporter drops and incomplete crash traces are expected failure modes, not reasons to repeat a committed verdict.
