# ADR 0007: PostgreSQL execution leases and trusted development agent

Accepted for Session 7.

Redis delivery and XAUTOCLAIM are transport ownership, not execution permission. The new `execution_ownership` row is the sole current execution authority for one submission. Its primary key permits only one current owner. It references the existing evaluation run through a composite run/submission/generation/owner foreign key. PostgreSQL increments generation only for a fresh attempt or permitted takeover, never for duplicate messages. Each immutable `evaluation_runs` row records its owner and outcome; there is no parallel result-history system.

The atomic claim locks the authorized principal's submission and ownership row, validates schema-2 event/submission/intent identity against a published outbox event, checks language and immutable suite metadata, then creates a run/lease. Only initial intent generation one is executable; rejudging remains absent. Duplicate work with a valid owner is retained, not executed or ACKed. Terminal replay verifies the committed submission/run/verdict/version and result fingerprint presence; exact report-persistence replay additionally compares fingerprints. Unsupported languages receive durable FAILED/null-verdict rejection records. Missing suite metadata is a visible infrastructure rejection, not silent QUEUED work.

An active lease can renew only while owner, run, generation, processing status and PostgreSQL expiry remain valid. Default lease/heartbeat are 30s/10s. Heartbeat runs independently of compile, runtime and finalization. Any renewal error is treated as uncertainty: cancel work immediately and prohibit subsequent result/failure writes. Recovery waits for DB expiry; an expired owner can never revive its lease. This conservative policy may repeat physical execution after a transient outage; it protects authoritative effects.

All existing result paths, including the local CLI and generic owned-submission transitions, now use the same fence. Local one-shot judging receives a bounded 180-second lease, longer than its bounded evaluation/cleanup/persistence window. Agent attempts use configurable renewable leases and immutable attempt budgets. Finalization locks submission then ownership then run; transaction-local identity plus database triggers recheck authority for per-case inserts, run completion and submission verdict. Completion and evidence remain one transaction, with a final ownership DONE transition. Replay after completed persistence is read-only and checks equivalence. Historical terminal records remain readable and immutable.

Recovery is PostgreSQL-driven, independent of Redis idle time, PEL ownership or entry survival. Bounded indexed scans select published unowned QUEUED work, expired ACTIVE agent work and due RETRY work for the configured principal. Takeover marks the old run FAILED/lease_expired and creates a higher generation atomically. Infrastructure failure records a failed run and schedules RETRY without resetting submission state; budget exhaustion makes submission FAILED with no user verdict. Terminal user verdicts never retry. An expired final attempt has a narrowly guarded recovery-only exhaustion transition. History and hidden-test references stay immutable.

The opt-in host-side `judge-agent` reuses the existing worker pool, queue schema, evaluator and restricted Docker backend. Pool and scanner share one bounded execution admission semaphore. SIGTERM stops polling/claims, permits bounded drain, then cancels unfinished work; lease/retry records preserve recovery. ACK follows verified durable completion or explicit terminal infrastructure rejection. A crash after commit/before ACK replays without execution. Redis outage can delay ACK while PostgreSQL results remain authoritative.

The agent requires a command flag, enable environment variable, development identity and isolated stream. It executes only that principal's submissions. It verifies pinned images and sandbox capabilities before accepting work. API, ordinary worker and relay images still omit all trusted controllers and receive no Docker authority. This is a controlled local development integration, not a production hostile-code service. Session 8 will harden Linux sandbox operations; it must preserve the ownership protocol rather than equating cancellation or Redis reclamation with fencing.
