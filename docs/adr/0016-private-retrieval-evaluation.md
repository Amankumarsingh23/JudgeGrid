# ADR 0016: frozen, owner-scoped repository retrieval evaluation

Status: accepted for Session 16 trusted development tooling.

Evaluate the existing READY source/analysis/retrieval chain and Session 15 context policy. Do not ingest HEAD, re-embed the corpus, add a migration, change production ranking, or introduce an answering/action endpoint. `repo-eval` is a separately built, explicitly gated operator binary; ordinary service images exclude it.

Freeze questions, source-span judgments, required facts, categories, splits and annotation provenance before evaluation. Keep actual questions, provisional labels, source captures and traces in ignored private storage. The committed fixture is newly authored synthetic text, explicitly safe to publish. Model-assisted labels remain provisional; the supported manifest refuses claims of independent human review. A mechanical stratified source/hash audit is not a second human annotator or an agreement measurement.

Use exact snapshot/file identities, half-open UTF-8 byte spans, byte-column line coordinates and selected-source SHA-256. Authorization comes from authoritative owner/READY joins, never a hash. A scoped offline capture verifies the real readers and all included source, rehashes cached spans on use, checks current owner/READY/manifest identities on every read, verifies actual dense vector/payload rows before SQL ranking, and rechecks full backing source/index integrity at checkpoints and before completed publication. This is explicit frozen-corpus evaluation, not a production read-cache optimization or a promise that every intermediate source fetch is fresh.

Reuse the production BM25, exact pgvector ranker, RRF and overlap grouping. A companion context ranking adapter reuses the existing graph expansion, paired model helper, source-span coordinate function and ranking function, and stops before MMR/packing. A real-source parity test compares it with the production builder's pre-selection output. The old builder/ranker/graph sources and Session 15 context-policy identity are preserved. V6 uses the unchanged builder and verifier. Per-session query vectors and scores may be reused only with matching source/model/input/window identities; no cross-owner or persistent semantic cache exists.

Report document rankings and context assembly order separately. Unknown results are not adjudicated negatives: expose judgment coverage, judged precision, conditional precision bounds and explicitly pooled zero-gain metrics. Known-positive recall and truncated AP use judged-pool denominators. Pooled nDCG/AP are **not mathematical lower bounds on whole-corpus quality**. Required-fact byte coverage and evidence sufficiency remain separate from document metrics and citation integrity. No actual LLM-answer groundedness is measured.

Use fixed K/depth budgets and existing untuned model/ranking settings. Seeded percentile bootstrap samples query IDs, pairing variants on common valid queries. No-positive queries and infrastructure failures have separate accounting; small categories are flagged. Query-level intervals do not remove correlated-topic, pooling, author or provisional-label bias.

Evaluation is serial, source/metadata/model bounded and deadline limited. Checkpoints bind benchmark/policy/owner, planned fresh measurements and completed variant rows, retaining failed attempts. Resumption verifies identities and source again, recomputes metrics and retries failed rows at most twice. Missing observations cannot become COMPLETE. Reports describe observed failures rather than substituting favorable variants or calling outages correct abstention.

Consequences: exact data and policy digests make comparisons reproducible; independent semantic review and a broader benchmark remain necessary. Native Windows agent failures from Session 15 remain open risks even when the hosted Linux workflow passes. Session 17 may consume verified evidence and evaluation diagnostics; this decision grants no planning, model-routing, tool, code-editing or PR authority.
