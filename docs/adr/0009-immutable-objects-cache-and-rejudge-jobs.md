# ADR 0009: Immutable private objects, fenced cache builds and logical rejudge jobs

Accepted 2026-10-28 for explicitly enabled trusted development controllers.

Embedded SQL migration files are stored without Git newline normalization so their byte-level checksums stay identical across Windows/Linux checkouts. Existing migration bytes and applied history remain unchanged.

PostgreSQL retains authoritative problem/version bindings, publication state, cache provenance, job identities, leases and selected results. S3 retains bounded private object bytes. Bundle serialization is the existing schema-one canonical JSON; the SHA-256, checker, ordered case IDs and individual hashes must agree with sealed database metadata. Hash integrity does not grant access: private buckets and credentials provide access control.

`objects.S3` uses minio-go v7.4.1, conditional single-part creation, enabled bucket versioning, bounded reads and read-back verification. Bundle and artifact buckets are separate. Workloads and ordinary API/worker/relay services receive no object credentials. A configured S3 failure never selects the local adapter. Legacy local operation remains the default for existing deployments; choosing S3 is explicit. Local and remote adapters satisfy the same bundle publisher/load boundary.

Publication commits a STAGED identity before upload, then uploads and verifies bytes before a transaction creates/seals the new version and activates the problem pointer. Repeating the exact operator/key/file resumes the operation; changed intent conflicts. PostgreSQL and S3 cannot commit atomically. Staged rows and potentially unreferenced objects remain for operator review; automatic object deletion is deliberately absent. An interrupted publication is resumed with the original trusted file. Published versions and old bindings cannot be edited.

The successful-C++ cache key includes schema, exact source hash, compiler path, pinned toolchain/build image, flags, target/ABI, image-contained dependencies, source-date policy, seccomp hash and compile resource budgets. Compilation is independent of problem/test versions; their identity is excluded. The compiler has no dependency downloads or external mutable headers. Source timestamps and SOURCE_DATE_EPOCH are fixed. amd64 ELF is the supported cache target, verified against the image platform. Other targets fail closed when caching is enabled.

Bounded execution slots constrain local waiters. All controllers use a database-backed single-flight BUILDING claim with owner, generation and bounded expiry (normally two minutes), rather than trusting a process-local lock. Only the matching unexpired builder can publish READY. A trusted controller exports a bounded regular artifact from its private compile container, validates ELF format, writes content-addressed bytes and verifies read-back before READY. Every hit rechecks hash, size and ELF format, then copies bytes into a new private artifact volume and uses the unchanged restricted runtime. No shared writable cache mount exists. Compilation errors are not cached. Corruption/outage fails closed; explicit metadata eviction permits rebuild and retains bytes. Cache hit evidence is marked as such: its preparation phase is not a new compiler invocation.

Rejudging does not reopen submissions. The original source/version/status/verdict remain sealed. Each request creates an `evaluation_jobs` identity plus one schema-three outbox reference. Each job has independent attempt generations and an ownership row; result runs remain in the existing immutable evaluation history with an explicit job link. Initial ownership and schema-two delivery remain compatible. Composite references and database result-write fencing distinguish job and attempt authority. Recovery scans include due rejudge jobs independently of Redis retention. Sandbox registry authorization resolves a run to its initial-submission or logical-job scope.

Request ordering serializes on the submission and assigns increasing ordinals. The latest requested job may update `selected_evaluations` only after its result and evidence commit; a later-finishing older job cannot replace it. If the latest job fails, the previously selected committed result remains. The public original version field stays original; selected run/version and original verdict accompany the displayed current verdict. Owner-scoped trusted history returns sanitized summaries, never hidden inputs or object references. There is no public administrative endpoint.

Namespaces, cgroups, seccomp, fresh runtimes, private stdin and existing null CPU/peak-memory semantics remain. Sandbox expiry cannot be revived, so registry cleanup checks the matching logical scope and database time under the execution creation/reconciliation guard; it does not lock an unrelated newer job's ownership row.

Limitations: the community MinIO server is archived and packaged images were unavailable in this environment. The development image builds pinned upstream release commit `07c3a429bfed433e49018cb0f78a52145d4bedeb` from source. This is not a recommendation for a new production storage deployment. Bucket versioning is not immutable retention against a privileged administrator. The local demonstration uses generated trusted operator credentials; deployment must provision narrower reader/builder roles. Object garbage collection and retention policy are deferred. Shared-kernel/daemon trust and aggregate sandbox-volume quota gaps remain from Session 8.
