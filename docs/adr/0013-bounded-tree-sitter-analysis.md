# ADR 0013: bounded Tree-sitter analysis of immutable snapshots

Status: accepted, Session 13.

The Go 1.26 controller must work on Windows and Linux, consume private READY source snapshots, and interrupt native parsing without pretending a Go context interrupts C. We keep the controller free of cgo and run an embedded, trusted Python CST extractor in a separate process. CPython 3.13 loads pinned compiled Tree-sitter wheels. `helper/requirements.lock` pins package versions and wheel SHA-256 hashes; `helper/lock.json` also pins installed Python/native module bytes on Windows AMD64 and Linux x86_64. The helper checks those bytes before importing grammars. `-I -B`, an operator-provided absolute interpreter, private temporary helper files, stdin-only source delivery and no repository imports keep source as data. Missing dependencies fail closed.

The helper inherits the existing ingestion process resource boundary: Linux `prlimit` (512 MiB virtual address space, 60 CPU seconds) and Windows suspended-start, 512 MiB kill-on-close job. Per-file wall deadlines terminate the process. These are resource controls; the trusted interpreter/native parser is not a general hostile-program sandbox. No compiler, repository script, package manager, hooks or repository-selected grammar runs during analysis. Installing trusted pinned binary wheels is an operator setup step. The tooling Dockerfile is separate from ordinary service images; neither Python nor `repo-analyze` is shipped in those images.

Go, Python, JavaScript/JSX, TypeScript and TSX receive real grammar parsing. C, C++, Java and other languages remain explicitly unsupported. Their eligible UTF-8 bytes may receive file-region chunks, with no invented syntax symbols. The extractor visits the concrete syntax tree, including punctuation/error nodes for resource accounting, and derives a smaller symbol table. This is neither a compiler nor complete type checking. Byte-positioned calls retain their syntax and evidence; language-aware local resolution is deliberately conservative. Dynamic dispatch, unknown receivers and external imports are not claimed as fully resolved dependencies.

Migration 0015 creates an independent private analysis domain. Index identity combines source snapshot and immutable analysis policy. Source manifest identity is retained unchanged. Database-clock claims, renewable leases, bounded attempts, token/generation checks, guarded staging and atomic publication prevent stale or incomplete READY indexes. Failures retain file-attempt diagnostics; READY manifests and rows are immutable. Native parser failure fails the index; recoverable syntax errors produce explicit PARTIAL files and candidate edges. Unsupported/excluded files remain accounted for.

The file-local cache is repository-scoped and keyed by raw bytes, grammar variant, helper/extractor identity and policy. Extractor identity hashes the trusted Python helper, grammar lock, compiled-in Go resolver and chunker sources, with canonical LF line endings. Changes to those algorithms therefore create a new identity. Facts contain no copied source or snapshot IDs. A different snapshot reconstructs IDs and resolves its entire graph again. Changing an imported declaration must invalidate the caller's old relationship even when the caller's parse facts are reused. We do not implement incremental Tree-sitter tree edits; reuse is whole-file facts with exact-byte verification.

Chunks retain exact source file/index/symbol provenance, half-open byte spans, byte-based line columns, content SHA-256 and structural context. Retrieval uses the existing owner-authorized source reader and verifies the extracted bytes again. Session 14 may enumerate this typed READY reader; no retrieval ranking, embeddings, vector index or LLM operation is part of this decision.

The tradeoff is one interpreter startup per supported file and a trusted Python operator dependency. Small bounded repositories fit the sequential implementation. Language/build configuration, aliases, reexports, package discovery and dynamic behavior remain incomplete by design. Extractor/resolver/chunker semantics are versioned by the policy; semantic changes require a policy version change. Pinned runtime reference: [py-tree-sitter](https://tree-sitter.github.io/py-tree-sitter/), [Tree-sitter syntax trees](https://tree-sitter.github.io/tree-sitter/using-parsers/2-basic-parsing.html).
