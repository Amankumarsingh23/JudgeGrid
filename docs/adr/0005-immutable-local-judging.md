# ADR 0005: Immutable suites and controlled local judging

Accepted for Session 5.

The first judge must connect durable submissions to real execution without granting Docker authority to the HTTP API or queue workers. A separate, explicitly opted-in `judge-local` controller owns one submission through a PostgreSQL session advisory lock. This is local ownership, not a distributed lease or fencing protocol.

Private test bundles are canonical JSON objects addressed by SHA-256. PostgreSQL seals a problem-version-to-bundle association, comparator, ordered case identifiers, sample flags and individual input/expected hashes. The trusted local adapter uses exclusive creation, read-only files, bounded reads, strict schema validation and complete hash/metadata verification. Operators own its directory. Filesystem permissions are not protection against the host administrator. No object-store service existed in this repository; an S3 adapter can implement the same load contract later. Private files never enter application images or Git.

C++ compiles once into a private volume; Python source is prepared once. Each case receives a fresh restricted container, process, stdin and temporary filesystem. Runtime mounts the artifact read-only. The checker and expected output stay outside the sandbox. There are at most 16 cases, 64 KiB input/expected per case, 1 MiB aggregate raw bundle data, 64 KiB combined runtime output per case and a 120-second evaluation context. Compilation has its own 15-second/256 MiB budget; runtime uses the immutable problem limits. Cleanup has an independent bounded context and must succeed before finalization.

`exact` compares every byte. `tokens` separates only ASCII space, tab, CR, LF, vertical tab and form feed. Token bytes remain significant, including Unicode and invalid UTF-8; extra tokens fail. Empty token streams match. Numeric tolerance is deferred. Comparators are explicit and immutable with the suite.

The evaluator stops at the first failing case. AC requires every required case to pass. Wrong output is WA; abnormal exits are RE; trusted timeout/output-limit outcomes become TLE/OLE. MLE requires Docker OOM evidence: exit 137 alone is RE. C++ compile failure or compile budget exhaustion yields CE with a distinct `compile_reason`. Cancellation, invalid configuration, unavailable images, controller errors, corrupted bundles and cleanup errors are infrastructure failures with no user verdict.

Beginning an evaluation atomically changes QUEUED to RUNNING and creates generation-one run identity. Finalization validates ordered evidence, locks that run, checks ownership/version/hash, performs CAS RUNNING to EVALUATING, inserts sanitized per-case evidence, completes the run and CASes EVALUATING to COMPLETED in one transaction. Only hashes, bounded counts and trusted outcome/measurement fields persist; raw output, diagnostics, input and expected output do not. Unavailable CPU time and peak memory remain null. Terminal runs and evidence are immutable.

Retries use the same run and report fingerprint. Identical completed reports replay; conflicting/stale reports fail. Persistence retries are bounded and never reexecute code. Infrastructure failure atomically sets run/submission FAILED with a safe reason and null verdict. A database outage cannot be reported as durable completion. Ambiguous commit outcomes can be inspected/replayed using the terminal run. A hard controller crash can leave RUNNING stranded; automatic reclaim/rejudging is deliberately absent. Session 6 adds outbox dispatch, followed by distributed ownership in later sessions.
