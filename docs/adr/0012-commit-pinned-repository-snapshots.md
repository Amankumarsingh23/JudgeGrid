# ADR 0012: separately authorized commit-pinned source snapshots

Status: accepted for trusted local development. Builds on Session 11 commit `56ea76e421eca19066362fdecedd4e9aae04521e`.

Repository intelligence is separate from judge execution. `repo-ingest` requires explicit local opt-in, development identity, an explicit database URL, an operator trust file and an explicit source-storage backend. It is absent from ordinary API/worker/relay images, has no Docker dependency, and introduces no public ingestion/browsing endpoint. PostgreSQL records one immutable repository owner and location/origin; hashes and object existence never authorize reads.

Use the installed, maintained Git executable as an object parser, with fixed argument arrays and a clean environment. Create a temporary bare view containing only our configuration. Read the approved repository's object database, validate its layout/size, and ignore its hooks, filters, includes, replacement refs, working tree and remotes. Resolve a restricted ref once, peel bounded annotated tags, verify commit/tree/blob object hashes, then enumerate the pinned tree directly. Both SHA-1 and SHA-256 object formats are supported. Never use checkout, textconv, filters, symlink following, submodule recursion or lazy fetch.

An explicitly approved public HTTPS fetch uses a short-lived loopback smart-HTTP broker. The broker allows only Git discovery/upload-pack paths at the exact approved origin, validates/pins public DNS addresses, verifies TLS, refuses redirects/proxies/credentials and bounds requests, downloaded bytes and time. Git receives a broker URL, not an arbitrary caller transport. Fetching populates an approved private bare mirror; its configuration remains untrusted and is never executed. Private remote authentication and custom Git transports are unsupported; provision an authorized local mirror for those repositories.

Snapshot identity hashes schema/repository UUID/object format/full commit/policy digest. Policy identity hashes its fixed scanner/selection version and all budgets/options. A canonical, byte-sorted JSON manifest contains the root tree and every enumerated tree entry, including explicit exclusions. File IDs hash snapshot identity/path. Included raw bytes use independent SHA-256 addressing. Changing policy creates another snapshot; retries retain the logical identity.

Keep source data in a separate private backend with repository-scoped keys. Reuse the project's conditional-write/versioned-S3 conventions, not its hidden-test/cache credentials or namespaces. A dedicated source MinIO instance/volume is provided locally. A rooted local adapter supports offline use; selecting S3 never falls back to local storage. Upload/readback and fenced catalog writes precede a final complete verification. PostgreSQL atomically inserts the file inventory and marks READY under an unexpired generation/token. Crashes can leave verified/staged objects; they cannot expose a partial READY manifest. Reconciliation only reports opaque references and retains unknown objects.

Every target commit gets a complete tree enumeration. Reuse is scoped by repository/policy/object format/blob OID and verifies stored bytes again. Rename/mode changes therefore update provenance while reusing contents. READY replay verifies the persisted manifest/inventory and source bytes instead of reinterpreting a moving branch. Historical publication statistics and current-call attempt statistics are separate.

Limits include metadata, entries, depth, candidate count/bytes, total path bytes, one blob reader, manifest bytes and deadlines. Linux requires `prlimit` (512 MiB address space and 60 CPU seconds per Git process); Windows attaches suspended Git to a 512 MiB job before resuming it and kills descendants on close. The CLI also sets a 64 MiB Go heap target, which is not a hard RSS limit. No Docker/cgroup administrator access is needed. Remote download is capped at 32 MiB/45 seconds; Git object storage at 256 MiB. This is bounded development ingestion, not arbitrary-scale indexing.

Secret detection is conservative evidence-based exclusion, not proof of secret absence. Excluded bytes are not published as source blobs. Raw excluded contents can still exist in the approved original/mirror Git object database. Source paths/bodies/digests/owners/commits never become telemetry labels or span attributes. Repository text remains untrusted data, including instructions embedded in documentation.

Consequences: trusted operator/OS/Git/database/storage-administrator boundaries remain; no parser sandbox for malformed Git is claimed beyond process limits. There is no repository deletion, ACL sharing, object GC, private HTTPS auth, LFS materialization, external submodule fetch, archive import, embedding, AST extraction or agent execution. Session 13 consumes the READY typed reader, not the working tree.
